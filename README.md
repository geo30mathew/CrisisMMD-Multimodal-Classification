
# CrisisMMD: Multimodal Classification of Informative Disaster-Related Social Media Posts

## Project Overview

This project investigates whether combining text and image information improves the identification of informative social media posts during natural disasters.

The system performs binary classification of posts as **Informative** or **Not Informative**, comparing text-only, image-only, early fusion and late fusion approaches.

This project was developed for COMP 1013 at the University of Adelaide.

## Dataset

**Dataset:** CrisisMMD (QCRI), informative classification task.

The dataset is accessed through Hugging Face using `QCRI/CrisisMMD`.

| Split | Samples |
|---|---:|
| Training | 13,608 |
| Validation | 2,237 |
| Testing | 2,237 |

Labels:
- `0`: Informative
- `1`: Not informative

## Methodology

### Feature Extraction

- **Text:** Pretrained DistilBERT, producing 768-dimensional embeddings.
- **Images:** Pretrained EfficientNet-B0, producing 1,280-dimensional embeddings.

### Classification Approaches

1. **Text-only:** Logistic regression using text embeddings.
2. **Image-only:** Logistic regression using image embeddings.
3. **Early fusion:** Concatenation of text and image embeddings (2,048 dimensions), followed by logistic regression.
4. **Late fusion:** Equal-weight averaging of text-only and image-only predicted probabilities.

The classifiers use standardisation and class-balanced logistic regression.

## Validation Results


| Approach | Accuracy | Macro-F1 |
|---|---:|---:|
| Text-only | 0.6969 | 0.6808 |
| Image-only | 0.7139 | 0.7026 |
| Early fusion | 0.7336 | 0.7200 |
| Late fusion | **0.7488** | **0.7344** |

Late fusion achieved the highest validation accuracy and macro-F1 among the evaluated approaches.

## Reproducibility

### Requirements

- Python 3
- Jupyter Notebook
- PyTorch
- Transformers
- Torchvision
- Hugging Face Datasets
- NumPy
- Pandas
- Scikit-learn
- Matplotlib
- Joblib

A CUDA-compatible GPU is recommended for feature extraction.

### Running the Project


### Running the Project

1. Clone or download this repository.
2. Create and activate a Python virtual environment.
3. Install the dependencies using:

   ```bash
   pip install -r requirements.txt
   ```

4. Open the project notebook in Jupyter.
5. Run the notebook in order, starting with dataset loading and preprocessing.
6. Extract and cache text and image embeddings.
7. Train and evaluate the classifiers.
8. Compare the fusion approaches and inspect the final evaluation results.

**Important:** The notebook uses cached embeddings and saved model artifacts in some sections. A complete fresh-environment reproduction has not yet been verified. Cached files may need to be regenerated by executing the relevant feature extraction cells. Some local paths may require adjustment.

### Saved Artifacts

The repository includes `crisismmd_features.npz`, which contains cached features for the preliminary pilot experiment (200 training and 50 validation samples).

The full-dataset feature embeddings and trained model files are not included in the repository because of their size.

The notebook generates model comparison figures, confusion matrices, evaluation metrics and other analysis outputs in local results directories.

To reproduce the full-dataset experiment, the required embeddings must be generated by running the feature extraction cells. This may take considerable time, and a CUDA-compatible GPU is recommended.


## Limitations

- Performance varies across disaster events.
- The model makes some high-confidence incorrect predictions.
- Cross-event generalisation requires further investigation.
- Qualitative image-error analysis was limited by image availability.
- Full inference time includes feature extraction and is greater than classifier-only inference time.
